# Карта аудита

Это рабочий список проверки по приложенному ТЗ. Наличие строки в таблице не заменяет запуск команды. Фактически выполненные проверки описаны в `VALIDATION.md` и `BROWSER-REPORT.md`.

| Пункт аудита | Где реализован | Как проверить |
|---|---|---|
| Структура, Go-модуль, три шрифта | Корень, `cmd/`, `internal/`, `templates/`, `static/` | `go list ./...`, список файлов |
| Генерация и три баннера | `internal/ascii`, форма | `hello` со всеми шрифтами; multiline и пустая строка |
| TXT совпадает с экраном | `internal/export`, hidden-поле формы | Сравнить `pre.textContent` и байты загрузки |
| Изменяемый файл | `scripts/download.sh`, README о правах браузера | `printf hello \| sh scripts/download.sh test.txt`, `ls -l test.txt` |
| Три обязательных заголовка | `internal/handlers` | `curl -D -` и сравнение Content-Length с размером тела |
| Повторный и разный экспорт | Чистые функции Build и изолированная статистика | Несколько POST по форматам и содержимому |
| Символы, строки, ширина, цвет | `internal/recommender` | JSON `/export-analyzer`; empty, ANSI, ширина 120/121 |
| Формулы размеров | `Analyze` | `hello/standard`: 256 / 1440 / 14880 |
| Правила выбора | `Analyze` | Цвет → HTML, ширина >120 → HTML, прочее → TXT |
| Отсутствие краша | Все обработчики и лимиты | Неверный JSON, размер, формат, шрифт, метод |
| Модульность и тесты | Пакеты `internal/` | `go test ./...`, `go vet ./...` |
| Bonus: Export Insights | `internal/insights`, `/export-insights` | Cookie-jar, два одинаковых экспорта и другой браузер |
| Bonus: оптимизация | `Summary.Optimization` | Совет зависит от наиболее частого формата |
| Bonus: PDF | `internal/export/pdf.go`, `go.mod` | Скачать, открыть; широкий и многостраничный рисунок |
| Bonus: PNG | `internal/export/png.go`, `font8x8.go` | Скачать, декодировать и проверить глифы/размер |
| Дополнительные функции базового symbol-web | `internal/textai` | Все три POST API в mock; ошибки настроенного backend |
| Удобство и доступность | Внешний CSS и формы | Клавиатура, 375/768/1920 px, видимый focus |

## Ручной маршрут аудитора

1. Запустить сервер без `LLM_BASE_URL` и открыть главную.
2. Получить `hello` в `standard`, сверить метрики с примером ТЗ.
3. Скачать TXT и HTML. Проверить сохранение пробелов и строк, HTML открыть отдельно.
4. Выгрузить PDF; попробовать длинный и широкий рисунок.
5. Скачать один рисунок дважды, обновить статистику; повторить в отдельном браузерном профиле.
6. Проверить ошибку неизвестного формата, пустую форму, кириллицу в генераторе и превышение лимита.
7. Попробовать mock-подсказки и выбор шрифта. Настроить недоступный LLM backend и убедиться в 503 без остановки генератора.
8. Пройти интерфейс клавишей Tab, изменить размер окна и включить уменьшенную анимацию ОС.

Проект не обещает защиту от бесконечного количества клиентов на одном компьютере. Лимиты действуют на запрос, сессию и обращения к модели. Нагрузочное тестирование выполняется ограниченным числом параллельных запросов, а для публичной эксплуатации нужны также ограничения входящего трафика на уровне инфраструктуры.
