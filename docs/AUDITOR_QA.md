# Вопросы аудитора и готовые объяснения

Документ помогает разобрать работу проекта. Вопросы покрывают требования, бонусы, границы и типичные изменения на защите. Конечный список не может охватить все возможные вопросы.

## Загрузка файла и HTTP

**Что происходит при нажатии «Скачать»?** Браузер передаёт показанный рисунок и формат на `/export`. Обработчик ограничивает тело запроса, проверяет поля и вызывает `export.Build`. Файл целиком формируется в памяти. Затем выставляются заголовки и отправляются готовые байты. Без JavaScript обычная HTML-форма также отправляет POST и получает вложение.

**Какие заголовки обязательны и зачем?** `Content-Type` объясняет формат. `Content-Length` сообщает точный размер тела в байтах. `Content-Disposition: attachment` предлагает скачать файл и передаёт безопасное имя.

**Почему длина считается после создания файла?** HTML добавляет разметку и экранирует символы, PDF сжимается. Размер исходного текста не равен размеру результата. Мы считаем `len(file.Data)`. Неверная длина может оборвать загрузку, вызвать ожидание несуществующих байтов или ошибку клиента.

**Чем `len` отличается от числа символов?** Go считает байты строки. Один символ Unicode может занимать несколько байтов; например, русская буква обычно занимает два байта. Для HTTP нужна длина байтов, не рун.

**Где создаётся временный файл?** На сервере он не создаётся. Каждый запрос имеет собственный буфер; два клиента не перезаписывают общий `symbol-art.txt`.

**Как вы выдаёте права 0644?** HTTP не умеет устанавливать POSIX-права на компьютере клиента. Обычную загрузку сохраняет браузер. При необходимости точного режима скрипт загрузки сохраняет файл и применяет `chmod 0644`: владелец читает и пишет, остальные только читают. Нельзя честно обещать управление правами Windows через HTTP-заголовок.

**Почему нельзя просто вставить имя пользователя в заголовок?** В имени могут оказаться переносы строк и путь. Мы берём последнее имя, убираем опасные символы, ограничиваем длину и задаём расширение по реально выбранному формату. `mime.FormatMediaType` кодирует Unicode по правилам заголовков.

**Что будет с `<script>` в рисунке?** В HTML он станет экранированным текстом. В интерфейсе работает `html/template`, в выгрузке — `html.EscapeString`. В TXT сохраняются исходные байты; текстовый файл не является HTML.

## Формулы и рекомендации

**Почему HTML умножается на 2.5 и прибавляется 800?** Это обязательная приближённая формула задания. Множитель отражает увеличение текста после экранирования, фиксированное слагаемое — каркас страницы и минимальный CSS. Это оценка, а не гарантия реального размера.

**Как считается PNG?** Ширина умножается на число строк и 60 байт на условную ячейку. Это грубая оценка из ТЗ; степень сжатия настоящего изображения зависит от рисунка.

**Как выбрать формат?** Сначала проверяем ANSI-цвет: HTML умеет представить его безопасными цветными span. Затем ширину: больше 120 — HTML с предупреждением о переносе в текстовых программах. Иначе TXT: самый простой и переносимый вариант.

**Сколько даёт пример `hello`?** 256 байт, 8 строк, ширина 31. TXT: 256. HTML: `256 × 2.5 + 800 = 1440`. PNG: `31 × 8 × 60 = 14880`. Цвета нет, ширина не больше 120, выбирается TXT.

**Что происходит ровно при ширине 120?** Без цвета выбирается TXT. Порог в ТЗ строгий: больше 120, значит HTML начинается со 121.

**Что при пустом содержимом?** Генератор веб-формы просит текст. Сам анализатор допускает пустую строку: 0 байт, 0 строк, 0 ширина; оценки 0, 800, 0; выбор TXT. Пустой TXT тоже корректный файл.

**Считается ли финальный `\n` девятой строкой?** Нет. Он завершает восьмую строку. Но дополнительные пустые строки внутри содержимого учитываются.

**Это искусственный интеллект?** Анализатор формата и выбор шрифта используют правила. Нейросеть работает только в отдельно настроенных текстовых подсказках. При отсутствии backend подсказки возвращает явный mock-режим.

## PDF, статистика и границы

**Почему TXT и HTML без библиотек, а PDF с библиотекой?** TXT — байты текста. HTML собирают шаблоны и экранирование из стандартной библиотеки. PDF требует шрифтов, объектов документа, страниц и таблицы ссылок; стандартная библиотека не предоставляет готового генератора. Внешний пакет разрешён именно для бонуса и зафиксирован в `go.mod`.

**Что будет с очень широким PDF?** Рисунок делится на горизонтальные панели фиксированной ширины и страницы по высоте. Символы не переносятся в середине строки, но для полного рисунка может потребоваться несколько листов. Ограничение 256 панелей предотвращает раздувание документа.

**Сохранит ли PDF ANSI-цвет?** Нет, он монохромный. Цветовой формат — HTML. Это явно написано в интерфейсе и README.

**Почему сессии не смешиваются?** Сервер выдаёт случайный идентификатор в HttpOnly-cookie и хранит статистику по нему. Текст и счётчики разных браузеров находятся в отдельных записях. Все изменения защищены mutex.

**Что считается экспортом?** Успешно подготовленный ответ `/export`. Отменённое окно сохранения браузер серверу не сообщает. Нельзя утверждать, что счётчик означает количество файлов на диске клиента.

**Как определяются повторы?** По SHA-256 исходных байтов рисунка, независимо от формата. Для сессии хранится ограниченное количество хешей. Это не обещание распознать любой повтор за всё время.

**Что будет после перезапуска?** Сессионная статистика и кэш исчезнут: они находятся в оперативной памяти. Для постоянного хранения и нескольких серверов потребуется внешний store, чего учебное задание не требует.

**Что мешает заполнить память?** Ограничены размер исходного текста, размер тела, размер рисунка, число сессий, хешей, записей кэша и параллельных вызовов модели. HTTP-тайм-ауты ограничивают медленные подключения. Общая защита от потока бесконечного числа клиентов требует настройки инфраструктуры.

## Алгоритм, тесты и изменения на защите

**Как из `hello` получается рисунок?** Для каждой из восьми строк шрифта берутся соответствующие строки всех пяти букв и соединяются слева направо. Пробелы справа не удаляются: они участвуют в выравнивании. Переводы строк разделяют блоки.

**Можно ли подставить `../../secret` вместо шрифта?** Нет, имя выбирается из уже загруженной карты трёх разрешённых шрифтов. Имя не превращается в путь пользовательского файла.

**Зачем `go:embed`?** Чтобы бинарный файл всегда содержал проверенные шаблоны, CSS, JavaScript и шрифты. Его не сломает запуск из другой рабочей папки.

**Какие тесты действительно полезны?** Пример из ТЗ и граничные значения ловят ошибку формул. Заголовки и сравнение тела ловят повреждение файла. HTML-инъекции проверяют безопасность выгрузки. Сессионные тесты проверяют изоляцию и повторы. Race detector проверяет конкурентный доступ, fuzzing пробует неожиданное содержимое. Ни один конечный набор тестов не доказывает отсутствие всех ошибок.

**Как добавить новый формат?** Добавить ветку сборки в `export.Build`, тип MIME, расширение, пункт формы, статистику и проверки. Новую формулу рекомендации нельзя выдумать молча: её нужно отдельно описать.

**Как работает PNG без внешней библиотеки?** Стандартный `image/png` кодирует изображение. Изображение собирается из встроенных public-domain данных растрового шрифта 8×8. Это данные символов, а не подключённая сторонняя Go-библиотека. Размеры проверяются до выделения изображения. ANSI удаляется, цветной экспорт остаётся в HTML.

**Как поменять порог ширины?** Изменить правило в `Analyze`, тесты на значения ниже, равные и выше порога, затем README и карту аудита. Обработчики HTTP менять не нужно.

**Что если модель не отвечает?** Контекст и HTTP-клиент ограничивают вызов десятью секундами. При недоступности ответ 503 и русское сообщение. Рисунок и экспорт продолжают работать, поскольку от модели не зависят. Подробности — `TEXT_AI.md`.
